# PRD 质量审查

审查用户指定的 PRD 及其可用附件，提供带证据、可执行的发现项。审查是质量反馈，不代替业务决策或正式批准；除非用户另行要求，不直接改写被审文档。

## 审查方式

1. 确认审查对象、版本和目标读者；读取 PRD 引用且当前可访问的材料。不可访问的附件明确列为证据缺口。
2. 结合需求类型和复杂度逐项判断适用性。每项标记通过、问题、不适用或无法判断；不要求所有 PRD 都必须有 ER 图、接口、复杂权限矩阵等内容。
3. 核查：目标/范围/成功指标；角色与流程闭环；状态与异常/恢复；规则和数据口径；字段来源与校验；页面交互状态；权限与敏感数据；集成边界、幂等/超时/补偿（适用时）；非功能指标来源；验收覆盖与追溯；开放问题、决策和版本信息。
4. 只报告文本或来源支持的问题。区分明确缺陷、歧义、缺失证据和建议；不得把个人偏好写成硬性规范。
5. 对问题评级：P0 = 阻断评审/实现的重大矛盾或高风险缺口；P1 = 核心流程、权限、数据或验收缺失；P2 = 局部歧义/可维护性问题；P3 = 低影响优化。给出定位、引用依据、影响和建议修复。
6. 形成结论：通过、有条件通过或不通过。列出阻断项、条件、适用项覆盖情况和复查建议。此结论仅是审查意见，不代表业务批准。

## 默认输出

```markdown
# PRD 审查报告
## 审查对象与范围
## 结论（通过/有条件通过/不通过）及理由
## Findings（按严重度排序）
| ID | 严重度 | 位置/引用 | 发现与依据 | 影响 | 修复建议 |
## 检查覆盖（通过/问题/不适用/无法判断）
## 证据缺口与待确认决策
## 复查条件
```

避免只输出勾选项或抽象建议。每个 finding 应能在 PRD 中定位；若未发现问题，说明审查范围和未能验证的部分。用户指定输出格式时遵循指定格式。
