# PRD 交互原型

根据 PRD 生成用于评审和沟通的原型。先判断需求的页面类型和关键流程，再选择合适的信息架构；后台列表只是可选模式，不是默认硬模板。

## 执行约定

- 以 PRD 已确认的角色、规则、权限、状态和范围为准。原型不得悄悄增加产品能力；为展示而补充的交互或数据明确标为演示假设。
- PRD 不完整时仍可按用户意图制作草案，同时列出会影响交互的假设、待确认问题及影响；不确定项不得伪装成已确认设计。
- 选择与需求匹配的页面形态，如列表、详情、仪表盘、看板、表单、分步流程或移动端。只实现适用且有评审价值的交互，不为满足通用清单强塞筛选、批量操作、分页等功能。
- 默认以单文件 HTML 作为轻量交付选项；用户指定技术栈、文件格式、设备或现有项目时遵从该要求并在项目内集成。用户未指定落盘路径时，先说明/提供交付内容，不擅自覆盖项目文件。
- 若使用 CDN、在线字体或占位图，说明需要网络；避免未知外链。原型应清楚标出模拟数据、模拟持久化和未实现的后端行为。
- 注重键盘操作、可见焦点、表单标签、对话框关闭方式和窄屏可用性；按用户目标决定响应式范围。

## 工作步骤

1. 提取页面目标、用户角色、主任务、关键状态和评审问题；识别需求类型与目标设备。
2. 选择最能表达任务的页面结构和主要交互，先覆盖主流程与影响决策的异常/空/加载状态。
3. 使用与评审目标相称的数据集，覆盖真实状态与边界情况；不要求固定条数。
4. 生成原型及简短说明：已实现的流程、模拟部分、假设和开放问题。原型应可启动或可预览，交互反馈与视觉状态一致。
5. 按适用范围核对链接/按钮、表单校验、状态切换、键盘操作、窄屏和外部依赖；不宣称未实际检查的功能已验证。

## 默认交付

若采用纯 HTML：提供完整 HTML5 文件，可使用 Tailwind CDN 和原生 JavaScript；避免引入未要求的框架/依赖。通过内联 SVG 或可靠占位内容表达图标/图片。按 PRD 选择 Modal、Drawer、Toast、分页、批量操作等组件，不强制全量实现。

交付说明包含：原型文件位置/内容、覆盖的用户流程、模拟行为、假设与开放问题、依赖网络的资源，以及已实际检查的范围。用户要求“仅代码”时遵守该格式，将必要假设放在代码注释中。
